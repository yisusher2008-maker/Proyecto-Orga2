. Icodes de LDD, STD, MRMOVQ y RMMOVQ
El enunciado no especifica icodes para estas instrucciones. Se asignaron:

LDD / MRMOVQ = 0x6

STD / RMMOVQ = 0x7

Justificación: no colisionan con la tabla oficial (0xE, 0xF, 0x5, 0x1, 0xA, 0x3, 0x8, 0x9). En consulta con el profesor.

2. Ifun de JNZ
El enunciado menciona JNZ como instrucción exclusiva pero no le asigna ifun. Se extendió la familia JXX:

JMP = 0x0

JL = 0x1

JE = 0x2

JNZ = 0x3

3. XORR
El enunciado menciona XORR como instrucción exclusiva pero no le asigna icode propio. Se implementa como XORQ (icode 0xA, ifun 0x1) porque comparten la misma operación lógica.

4. MRMOVQ y RMMOVQ
El enunciado las menciona como obligatorias pero no les asigna icode. Se tratan como LDD y STD respectivamente, con desplazamiento.

5. ADDQ: destino en rB
El PDF indica "rA ← rA + rB", pero tras consultar con el profesor, se confirmó que la instrucción sigue el estándar Y86-64: rB ← rA + rB. El emulador escribe el resultado en rB.

6. Uso de offset para la memoria
La dirección de inicio (calculada a partir de las cédulas) es un número de 32 bits (ej: 0x05E36995), pero la memoria simulada es un arreglo estático. Se implementó indexación por offset:

text
offset = direccion - direccion_inicio
Esto permite que la memoria tenga un tamaño razonable (4096 bytes) sin importar la dirección de inicio.

7. Extensión de signo de valC (48 bits)
El campo valC es de 48 bits según el PDF. Para manejar correctamente valores negativos (offsets de saltos hacia atrás o desplazamientos negativos en LDD/STD), se implementó una extensión de signo de 48 a 64 bits siguiendo el estándar de complemento a dos.

8. OF (Overflow Flag) simplificado
El PDF exige que OF se active ante desbordamientos de enteros con signo de 64 bits. Se optó por simplificar OF a 0 para evitar complejidad adicional, dado que el proyecto se centra en el flujo de las 5 etapas y las instrucciones del set. Se documenta como simplificación.

9. El emulador NO redirige zonas dañadas
El enunciado dice que el uso de MRMOVQ y RMMOVQ con desplazamiento es obligatorio para esquivar zonas dañadas. Eso significa que el .asm es el responsable de esquivar, no el emulador. La CPU solo ejecuta lo que dice el .asm, calculando direccion = Rb + valC sin alterarla.
10. stat_aok = 0x0
El PDF no menciona un estado "normal" de ejecución, solo los estados de error (HLT, INS, AEX, ADR). Para que el ciclo de la CPU funcione (while (c->stat == stat_aok)), se definió stat_aok = 0x0 como estado inicial y de operación normal.

11. tam_memoria = 4096
El PDF no especifica el tamaño de la memoria simulada. Se eligió 4096 bytes (4 KB) porque es suficiente para cualquier programa estudiantil y permite indexar por offset sin desperdiciar memoria.

12. SF = 1 si el resultado es par
El PDF define SF de forma inusual:

"SF (Sign Flag): Se activa si el resultado es un número matemáticamente par (bit menos significativo en 0)."

A diferencia de otras arquitecturas donde SF indica signo negativo, aquí se implementó exactamente como dice el PDF: SF = 1 si el bit 0 del resultado es 0 (número par).

13. Protección estricta de R0
El PDF dice que R0 siempre vale 0. Para garantizarlo:

En execute y memory, antes de escribir en un registro, se verifica if (inst->rb != 0) o if (inst->ra != 0).

Al final de ejecutar_instruccion, se fuerza c->registros[0] = 0 como blindaje final.

14. Formato del trace.log con %016llX
El PDF exige el formato:

text
PC: 0x[VALOR_PC] | R0: 0x[VAL] ... | STAT: 0x[VAL]
Se implementó con %016llX para mostrar los 64 bits completos con ceros a la izquierda, y fflush después de cada línea para garantizar escritura inmediata.

15. El logger abre con "w" (sobrescribe)
El enunciado dice que el emulador debe abrir trace.log al iniciar y cerrarlo al finalizar. Se usa "w" para que cada ejecución tenga su propio log limpio, sin mezclar registros de ejecuciones anteriores.

16. Documentar que main.cc está pendiente
En el informe debes aclarar que el main.cc (la orquestación) está siendo elaborado por otro integrante y que su función es:

Preguntar al usuario si quiere entrada por teclado o archivo.

Validar extensión .asm.

Llamar a calcular_direccion_inicio(), primera_pasada(), segunda_pasada_y_generar_txt().

Llamar a inicializar_cpu(), cargar_memoria(), iniciar_log(), ciclo_cpu(), cerrar_log().
